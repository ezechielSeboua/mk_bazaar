## 4. Suivi de commande (client)

**Statut : à faire.**

Page publique accessible via le numéro de commande (ex. `MK-XXXX-YYYY`).

### Backend
- [ ] `GET /api/orders/track/{order_number}` — endpoint public (sans auth)
  - Retourne : statut, date, articles (nom + qté), montant total, zone de livraison
  - Ne retourne PAS les infos personnelles complètes (juste initiales du nom)

### Frontend
- [ ] Page `/suivi` avec un champ de saisie du numéro de commande
- [ ] Affichage du statut avec stepper visuel (`En attente` → `En traitement` → `Livré`)
- [ ] Lien vers cette page dans le mail/SMS de confirmation (si applicable)
- [ ] Ajouter le numéro de commande visible sur la page de confirmation de commande (`BasketPage`)

## 10. Optimisation des images produit

**Statut : à faire (recommandé avant lancement V2).**

Actuellement les images sont stockées sans compression (jusqu'à 4 Mo par fichier).

### Option recommandée : compression côté frontend
- [ ] Installer `browser-image-compression`
- [ ] Dans `ProductsPage`, compresser avant upload : `maxSizeMB: 1`, `maxWidthOrHeight: 1920`
- [ ] Afficher une progress bar pendant la compression

### Option alternative : Cloudinary
- [ ] Créer un compte Cloudinary gratuit
- [ ] Remplacer `$file->store()` par upload Cloudinary avec `f_auto,q_auto`
- [ ] Stocker l'URL Cloudinary au lieu du chemin local
